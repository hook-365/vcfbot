[ how this works ]

vcfbot.

A local research console for VMware Cloud Foundation documentation. Reads Broadcom's official PDF, splits it into passages, indexes them into a vector space, then uses retrieval-augmented generation to answer questions with page-accurate citations.

pipeline

fetch  →  extract  →  chunk  →  embed  →  retrieve  →  answer
httpx     pymupdf     tiktoken   nomic     chroma      qwen3
  1. fetchdownloads the master VCF PDF from Broadcom's CDN (one monolithic 9,158-page file)
  2. extractPyMuPDF splits each page into text and walks the document outline for hierarchical section paths
  3. chunk~800-token windows with overlap, preserving page ranges so every chunk knows where it came from
  4. embednomic-embed-text-v1.5 (Q8) maps each chunk into a 768-dimensional vector with role prefixes
  5. retrieveyour question is embedded the same way; the closest chunks by cosine similarity are pulled
  6. answerQwen3 reads only the retrieved snippets, synthesizes an answer, and cites every claim

citations

Every factual claim is followed by an inline marker like [vmware-cloud-foundation-9-1 p.1844]. Click any citation pill to scroll-spotlight the matching source card. ⌘+click jumps directly to the source PDF on Broadcom's CDN at that exact page.

privacy

Nothing leaves the host. The PDF, vector store, embedding model, and chat model all run locally. Questions are never sent to a third party.

caveats

This is RAG, not magic. The model can still be wrong — always check the cited source. If the answer says "the context does not specify…", retrieval missed; try rephrasing the question or making it more specific.
